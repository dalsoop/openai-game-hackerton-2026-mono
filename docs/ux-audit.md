# 다굴(Gang-Up) UI/UX 사용성 감사 보고서

## 1. 첫 접근 경험 (FTUE)

### 1.1 URL 접속 → 첫 화면
- HTML 로딩 화면(`index.html`)이 게임 타이틀("다굴 같이하기"), 부제("8명 · 한 판 · 마지막 한 명"), 로딩 바를 보여줌 → **양호**
- 로딩 이미지(`index.png`)가 있음 → 세계관 전달 가능
- 문제: Godot WASM(약 39MB + 29MB PCK)이 로드되면 바로 로비 화면으로 전환됨. HTML 로딩 → Godot 로비 사이에 **전환 인사가 없음**. 사용자는 "로딩이 끝났나?" 하는 순간 갑자기 다른 UI가 뜸

### 1.2 3분 안에 플레이 시작 가능한가?
- 로비에서 "연습하기 (로컬)" 버튼을 누르면 바로 대기실 → 게임 시작 가능 → **가능**
- 다만 온라인 방 만들기는 허브 연결이 필요하고, 연결 실패 시 에러 메시지가 기술적("허브 클라이언트가 없습니다") → 일반 사용자에게 불친절

### 1.3 조작 방법 표시
- 로비 헤더에 "조작" 버튼이 있어 누르면 `how_to_play_popup`이 뜸 → **있음**
- 문제: 인게임에서는 조작 안내가 없음. 첫 게임에 진입한 사용자가 WASD/마우스/Shift/Q/E를 모르면 아무것도 할 수 없음
- surviv.io는 첫 접속 시 화면 중앙에 조작 오버레이를 3초간 보여줌

### 1.4 로딩 시간 중 표시
- HTML 로딩 바가 있음 (gradient 스타일) → **양호**
- 퍼센트 숫자는 없음 → 추가하면 좋음
- 로딩 중 게임 팁을 보여주면 대기 시간이 덜 지루해짐

## 2. 화면별 UX 평가

### 2.1 로비 (lobby_builder.gd)

**구조**: 상단 헤더(타이틀+상태+버튼) + 좌측 사이드바(닉네임+방 만들기+연습) + 우측 방 목록

| 항목 | 평가 | 비고 |
|---|---|---|
| 정보 계층 | ⚠️ 불명확 | 부제("다굴 — 8인 배틀로얄")가 14px로 작고, 메인 카피("방을 만들거나 들어가세요")가 30px로 큼. 게임 이름이 부제처럼 보임 |
| 버튼 크기 | ✅ 적절 | "방 만들기" 60px, "연습하기" 52px. 터치에 충분 |
| 사이드바 너비 | ⚠️ 고정 320px | 모바일 웹(좁은 화면)에서 방 목록 영역이 너무 좁아질 수 있음 |
| 방 목록 행 | ✅ 양호 | 타이틀 + 모드 + 인원수 + 참가/관전 버튼이 한 줄에 잘 배치됨 |
| 상태 표시 | ✅ 양호 | 허브 연결 상태가 색상 코드(초록/빨강/주황)로 표시됨 |
| 닉네임 입력 | ⚠️ 설명 부족 | "닉네임" 라벨만 있고 왜 입력해야 하는지 설명 없음. placeholder가 없음 |
| 빈 방 목록 | ✅ 양호 | "열린 방이 없습니다. 방을 만들어 시작하세요!" 메시지가 표시됨 |
| 에러 메시지 | ⚠️ 기술적 | "허브 클라이언트가 없습니다" → 사용자 친화적이지 않음. "서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요"가 나음 |

### 2.2 대기실 (room_builder.gd)

**구조**: 상단 헤더(뒤로+타이틀+소리/설정) + 중앙 8인 슬롯(원형 배치) + 하단(채팅+시작 버튼+팁)

| 항목 | 평가 | 비고 |
|---|---|---|
| 8인 슬롯 | ✅ 직관적 | 원형 배치, 슬롯 색상 배지, 동물 이모지/이미지, 상태(호스트/대기 중/재접속 대기) |
| 호스트/게스트 구분 | ✅ 명확 | 파란색 "호스트", 녹색 "대기 중", 빨간색 "재접속 대기" |
| 게임 시작 조건 | ⚠️ 불명확 | 호스트만 "게임 시작" 버튼이 보이고, 게스트는 "호스트가 시작하면 출발합니다" 텍스트만. 언제 시작하는지 불확실 |
| 채팅 | ✅ 양호 | 전송 버튼 + 입력란이 있고 시스템 메시지가 색상으로 구분됨 |
| 모드 칩 | ✅ 제거됨 | full 1종이라 모드 선택 행이 `visible = false`로 숨겨짐 |
| 내보내기 버튼 | ✅ 호스트에게만 표시 | 적절한 권한 구분 |
| CPU 자동 참여 | ✅ 명시 | "CPU 자동 참여" 패널과 "빈 자리는 시작 시 CPU가 채웁니다" 메시지 |
| 모드 라벨 | ⚠️ 불필요한 공간 | 모드가 1개인데도 `wait_mode_label`이 "방 이름 | 최후의 1인이 승리합니다!"를 표시 — 방 이름만으로 충분 |

### 2.3 인게임 HUD (hud.gd)

| 항목 | 평가 | 비고 |
|---|---|---|
| 체력바 | ✅ 있음 | 하단 중앙, HP 숫자 + 바. 34% 이하에서 빨간색 전환 |
| 궁극기 게이지 | ✅ 있음 | 체력바 아래 파란 바 |
| 탄약 | ⚠️ 불명확 | `_draw_ammo_slot`이 있지만 호출되는지 확인 필요 |
| 킬 피드 | ⚠️ 없음 | 누가 누굴 잡았는지 실시간 피드가 없음. 킬 수만 좌상단에 표시 |
| 미니맵 | ✅ 있음 | 우상단 원형 미니맵, 세이프존 표시, 플레이어 위치 점 |
| 세이프존 타이머 | ✅ 있음 | 미니맵 아래에 "축소까지 N초" + 남은 시간 |
| 크로스헤어 | ✅ 있음 | `_draw_crosshair` 존재 |
| 현상금(wanted) | ✅ 있음 | `_draw_wanted_banner` — 가장 많이 킬한 사람 표시 |
| 스코어보드 | ✅ 있음 | `hud_mode == 1`에서 표시 (F2로 토글 추정) |
| HUD 토글 | ✅ 있음 | F1/F2/F3 모드 |
| 긴급 경고 | ✅ 있음 | 남은 시간 10초 이하에서 화면 테두리가 빨간색으로 깜빡 |

### 2.4 도움말 (how_to_play_popup.gd)

| 항목 | 평가 | 비고 |
|---|---|---|
| 조작 설명 | ✅ 충분 | WASD/마우스/좌클릭/우클릭/SHIFT/SPACE/Q/E + 터치 설명 |
| 규칙 설명 | ⚠️ 최소 | "최후의 1인이 승리합니다. 안전 구역은 시간이 지나면 줄어듭니다." 한 줄뿐 |
| 시각적 보조 | ❌ 없음 | 이미지, 다이어그램, 아이콘이 전혀 없음. 텍스트만으로 구성 |
| 닫기 | ✅ 양호 | "뒤로" 버튼 |

## 3. 접근성

| 항목 | 평가 | 비고 |
|---|---|---|
| 색각 이상 | ⚠️ 위험 | 8인 슬롯 색상 중 초록(#9bc53d)과 주황(#fa7921)이 적녹 색맹에게 구분 어려움. 미니맵 점도 색상에만 의존 |
| 폰트 크기 | ✅ 대체로 양호 | 메인 카피 30px, 본문 15~18px, 상태 13~14px. 웹에서 읽기 적절 |
| 터치 지원 | ✅ 있음 | touch_buttons.gd가 터치 조이스틱을 제공. 설정에서 조작 모드 선택 가능 |
| 키보드 내비게이션 | ❌ 없음 | Tab 키로 UI 요소를 이동할 수 없음 (코드 전용 UI라 focus 설정 없음) |
| 화면 크기 반응 | ⚠️ 고정 비율 | viewport 1600×900 고정, stretch mode "canvas_items". 극단적 종횡비에서 레터박스 |

## 4. 업계 비교

### surviv.io와 비교
| 항목 | surviv.io | 다굴 | 평가 |
|---|---|---|---|
| 첫 화면 → 게임 시작 | 이름 입력 + "Play" 1클릭 | 이름 입력 + "연습하기" 또는 "방 만들기" → 대기실 → 시작 | ⚠️ 다굴이 2~3단계 더 많음 |
| 인게임 조작 안내 | 첫 접속 시 오버레이 | 로비에서 "조작" 버튼 | ⚠️ 인게임 오버레이 없음 |
| 킬 피드 | 화면 좌상단 실시간 | 없음 | ❌ 부족 |
| 미니맵 | 우하단 사각형 | 우상단 원형 | ✅ 비슷 |
| 로딩 | 매우 빠름 (경량) | WASM 39MB + PCK 29MB | ⚠️ 느림 |

### agar.io와 비교
| 항목 | agar.io | 다굴 | 평가 |
|---|---|---|---|
| 진입 장벽 | 이름 입력 + Play | 방 시스템 필요 | ⚠️ 다굴이 복잡 |
| 리더보드 | 실시간 우측 | 좌상단 킬 수 | ✅ 비슷 |

### 다굴의 강점
- 8인 슬롯의 시각적 구성(원형 배치, 동물 이모지)이 독특
- 채팅 시스템이 있어 소통 가능
- 미니맵 + 세이프존 타이머가 잘 구현됨
- 조작 모드(자동/터치/키보드) 선택이 가능

## 5. 개선 제안

### P0 — 이것 없으면 플레이 불가
1. **인게임 첫 접속 조작 오버레이**: 게임 시작 후 3초간 "WASD 이동 / 마우스 조준 / 좌클릭 공격 / Shift 대시" 오버레이 표시. 한 번만 보여주고 localStorage에 기록
2. **에러 메시지 사용자화**: "허브 클라이언트가 없습니다" → "서버에 연결할 수 없습니다"

### P1 — 이것 없으면 경험이 나쁨
3. **킬 피드 추가**: 좌상단 또는 우상단에 "A가 B를 제거했습니다" 실시간 피드 (5초간 표시 후 사라짐)
4. **정보 계층 재정리**: 로비 타이틀을 "다굴" 30px + "8인 배틀로얄" 부제로 반전 (게임 이름이 눈에 먼저 들어와야 함)
5. **빠른 시작 경로**: "바로 시작" 버튼 → 빈 방이 있으면 자동 참가, 없으면 자동 생성. 1클릭 플레이
6. **대기실 모드 라벨 간소화**: 모드가 1종이므로 "최후의 1인이 승리합니다!" 만 남기고 모드명 제거
7. **HTML→Godot 전환 부드럽게**: WASM 로드 완료 후 0.5초 페이드 아웃으로 자연스럽게 전환

### P2 — 있으면 좋음
8. **로딩 팁**: HTML 로딩 중 게임 팁 로테이션 ("Shift로 대시할 수 있습니다", "안전 구역 밖에서는 체력이 줄어듭니다")
9. **색각 이상 대응**: 슬롯 색상에 패턴(줄무늬/점선) 추가하거나, 슬롯 번호를 크게 표시
10. **도움말에 시각 보조**: 키 아이콘이나 간단한 다이어그램 추가
11. **게임 종료 후 결과 화면**: 순위, 킬 수, 생존 시간을 보여주는 결과 화면 (현재는 로비로 돌아가는 것으로 추정)
12. **사운드 피드백**: 버튼 클릭, 방 입장, 게임 시작 시 효과음 (game_audio.gd 활용)
13. **반응형 레이아웃**: 사이드바 320px 고정 → 화면 너비에 비례하도록
