# 0007. Harbor 푸시가 실패하면 k3s-prod 노드에 이미지를 직접 적재하고 계속한다

- 날짜: 2026-08-28 (커밋 c51e56b에서 푸시 실패를 즉시 실패로 바꿈, 3c49a9f에서 단일 노드 예외 추가, a9cb4ba에서 노드 수와 무관하게 k3s-prod 적재로 확정)
- 상태: 채택

## 배경

배포 러너가 공인 DNS(1.1.1.1)로는 내부 Harbor 레지스트리 이름을 찾지 못해 `docker push`가 실패했다. 푸시 실패를 조용히 넘기면 이미지가 한 노드에만 있다는 사실이 숨겨진다.

## 결정

`docker push`를 3회 시도한다. 실패하면 준비된 노드 수를 보고, 1개 이상이면 경고를 남기고 `k3s ctr import`로 k3s-prod 노드에 이미지를 직접 넣은 뒤 계속한다. 준비된 노드가 0개일 때만 ship을 실패로 끝낸다. 허브는 차트의 `nodeSelector: k3s-prod`로 그 노드에만 뜨므로 다른 노드에 이미지가 없어도 기동에는 문제가 없다.

## 검토한 대안

- 푸시 실패 시 항상 실패(c51e56b): 러너 DNS 문제만으로 모든 배포가 막혔다.
- 단일 노드일 때만 예외(3c49a9f): 허브 Pod가 적재 대상인 k3s-prod에 고정되어 있으므로 노드 수를 따질 필요가 없다는 이유로 a9cb4ba에서 이 조건을 풀었다.

## 결과

- 허브를 k3s-prod 밖의 노드로 옮기거나 여러 노드에 퍼뜨리려면 먼저 Harbor 이름 해석(내부 DNS)을 해결해야 한다.
- 러너는 `/etc/hosts`에 Harbor 내부 IP(`HACKERTONE_HARBOR_IP`)를 적어 이름 해석을 시도한다. 커밋 a9cb4ba 시점의 러너에는 `/etc/hosts`를 쓸 권한이 없었다.
