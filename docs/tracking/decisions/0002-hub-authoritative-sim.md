# 0002. dagul-prod 허브가 경기 시뮬을 TypeScript로 직접 돌린다

- 날짜: 2026-08-26 (커밋 ee87cf2 "Give the prod hub the match sim so guests no longer aim through the host client."), 이후 c3faac9(생존 규칙), e3deec1(전투 모듈)로 확장
- 상태: 채택

## 배경

개발 슬롯 구조에서는 방장 브라우저의 Godot이 시뮬을 돌리고 허브는 방장의 스냅을 게스트에게, 게스트 입력을 방장에게 중계했다. 이 구조에서는 게스트의 조준과 입력이 방장 클라이언트를 거쳐서 반영됐다.

## 결정

`dagul-prod` 허브(`web/lib/hub/match-*.ts`)가 60Hz 고정 틱으로 경기 전체를 시뮬하고, 모든 클라이언트는 입력만 보내고 스냅을 받아 그린다. 규칙과 수치는 원본 GDScript(`game-pjh-gang-up`, `server-pjh-dev1`)를 결정론적으로 포팅한다.

## 검토한 대안

- 방장 클라이언트 권위 + 허브 중계(개발 슬롯 방식): 게스트 입력이 방장 클라이언트를 거쳐 반영되는 문제로 운영 슬롯에서 버렸다. 개발 슬롯에는 이 방식이 그대로 남아 있다.

## 결과

- 같은 게임 규칙이 GDScript(원본·개발 슬롯)와 TypeScript(`dagul-prod`) 두 벌로 존재한다. 규칙을 바꾸면 어느 쪽이 기준인지 정하고 다른 쪽과의 차이를 감수해야 한다.
- 스냅 필드는 TS 스키마·JSON 스냅과 Godot 스냅 해석기(`snap_contract.gd`) 양쪽에 맞춰야 한다. 스키마 클래스당 필드 64개 한도와 인코더 버퍼 크기가 제약이 된다.
- 방장이 나가도 서버가 시뮬을 계속하므로 경기 중 방장 승계가 시뮬 이전을 뜻하지 않는다.
- 허브 CPU가 동시 경기 수를 제한한다. 프로세스당 목표 동접은 500이다.
