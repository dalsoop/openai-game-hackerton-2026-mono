# 애니메이션 디자인

## 0. 제작 방식 — 본 애니메이션 대신 시퀀스 텍스처
- **본(스켈레톤) 리깅 기반 2D 애니메이션은 채택하지 않는다.** AI 도구로 본 웨이팅·애니메이션 보간을 안정적으로 잡기는 어렵다고 판단했기 때문.
- 대신 프레임 단위로 낱장 이미지를 뽑는 **시퀀스 텍스처(스프라이트 시트) 방식**으로 제작한다 — 각 동작은 정해진 프레임 수의 개별 이미지를 순서대로 재생하는 형태.
- 이 결정은 바로 아래 1장 "제작 난이도를 낮추는 방향" 원칙들(idle 루프 생략, 워크/런 통합)과 같은 맥락이다 — 본이 없으니 애니메이션 하나당 필요한 프레임 수 자체를 최소화하는 방향으로 설계가 이어진다.
- 실무 영향:
  - 좌우 방향 전환은 리깅 미러링이 아니라 **텍스처 자체를 좌우 반전(flip)**하거나 별도 프레임셋으로 준비.
  - 애니메이션이 하나 늘어날 때마다 원화/AI 생성 프레임 수가 그대로 제작 비용이 된다 → 2장 공용 애니메이션, 3장 개별 액션의 우선순위를 정할 때 **프레임 수 예산**도 함께 고려해야 함.
  - 수달 콤비처럼 2마리가 동기화되는 협동 액션도 본 정렬이 아니라 **프레임 시퀀스 자체를 맞물리게 그리는 방식**으로 제작(4장 2번 참고).

## 1. 기본 원칙 — 제작 난이도를 낮추는 방향
- **idle 루프 애니메이션은 만들지 않는다.** 가만히 있을 때는 **캐릭터 디자인** 페이지 5-3의 기본 서 있는 정지 포즈 1장을 그대로 쓴다 — 숨쉬기 등 미세 반복 동작을 위한 별도 루프를 원화·리깅할 필요가 없다.
- 대신 **한 자리에 3~5초 이상 멈춰 있으면 파티클 이펙트를 재생**해서 "가만히 있어도 심심해 보이지 않는" 효과를 애니메이션이 아닌 이펙트로 대체한다 — 이펙트 목록은 **파티클 디자인** 페이지 참고. 파티클은 정지 포즈 위에 얹기만 하면 되므로 스켈레톤 애니메이션보다 제작 비용이 훨씬 낮다.
- **이동 애니메이션은 걷기/뛰기를 구분하지 않고 "뛰는 모션" 하나로 통일**한다. 서서 뛰어다니는 느낌을 기본값으로 잡고, 이동 상태 전체(느린 이동이든 빠른 이동이든)를 이 사이클 하나의 재생 속도만 조절해서 커버한다 — 워크 사이클과 런 사이클을 별도로 만들지 않아도 된다.

## 2. 공용 애니메이션 (전 캐릭터 1세트로 재사용)
| # | 애니메이션 | 용도 |
|---|---|---|
| 1 | 기본 서 있는 자세 (정지 포즈) | 대기 상태 전체를 담당 — idle 루프 대체 |
| 2 | 이동(뛰기) 모션 | 워크·런 구분 없이 이동 전체를 커버하는 단일 사이클 |
| 3 *(제안)* | 성공 리액션 | 미니게임 결과 화면 공통 재사용 — 예: 방방 뛰며 양팔 들기 |
| 4 *(제안)* | 실패 리액션 | 미니게임 결과 화면 공통 재사용 — 예: 어깨 축 늘어뜨리기 |
| 5 *(제안)* | 캡슐 등장 모션 | 캡슐을 뽑아 미니게임에 입장할 때 "짠" 하고 튀어나오는 연출, 세계관의 캡슐뽑기 컨셉과 직결되므로 전 캐릭터 공통으로 만들어두면 재사용 가치가 높음 |

3~5번은 원문에는 없었지만, **미니게임 디자인** 페이지에서 이미 "입장→플레이→결과"라는 공통 플로우가 필요하다고 짚었던 부분과 맞물려 있어 애니메이션 목록에도 반영해봤다.

## 4. 추가로 정리가 필요해 보이는 항목 (AI 제안)
1. **개별 액션 애니메이션의 실제 우선순위** — 3장에서 19종 전체 목록은 뽑았지만, **미니게임 디자인** 페이지에서 언급된 "출시 시점 미니게임 개수"가 정해져야 실제로 몇 개의 개별 액션부터 제작할지 정해진다.
2. **협동 애니메이션(수달 콤비)의 프레임 시퀀스 제작 방식** — 3장의 수달 콤비 동기화 액션은 캐릭터 2개가 하나의 애니메이션처럼 맞물려야 하므로, 개별 동물의 단일 프레임셋과는 제작 방식(동기화된 프레임 쌍을 세트로 관리하는 방법 등)이 달라질 수 있다 — 별도 검토 필요.
3. **성공/실패/등장 애니메이션의 실제 채택 여부** — 2장의 3~5번은 AI 제안 상태라, 정말 전 캐릭터 공통으로 갈지 동물별로 다르게 갈지 결정이 필요하다.

## 5. AI 이미지 생성 파이프라인 계획 — 시퀀스 프레임을 실제로 뽑는 방법
0장에서 정한 "본 없이 시퀀스 텍스처로 만든다"를 실제로 실행하는 계획. 현재 구상은 **툴을 역할별로 나누는 것** — 캐릭터 초안(앵커) 이미지는 **코덱스**가 만들고, 실제 움직이는 시퀀스는 **시댄스(이미지→영상 생성 툴)**로 만든다는 전제로 아래 순서를 정리했다. 이미지 생성 작업에 착수할 때(코덱스가 이 문서를 읽고 초안 생성 작업을 진행할 때 포함) 이 순서를 따른다.

### 5-1. 핵심 리스크 — 무엇이 문제고, 어떻게 줄어드는가
AI 이미지 생성은 같은 캐릭터를 포즈·동작별로 매번 독립적으로 새로 생성하면 색상·비율·실루엣이 장마다 미세하게 흔들린다. **시댄스처럼 이미지 한 장을 입력받아 영상(연속 프레임)을 뽑아주는 툴을 쓰면, 한 번의 생성 안에서 프레임들이 시간적으로 이어져 나오기 때문에 프레임을 한 장씩 따로 생성하는 것보다 이 흔들림 문제는 상당히 줄어든다.**
- 대신 새로운 리스크가 생긴다: 영상 생성 모델은 그라데이션·모션 블러 쪽에 최적화된 경우가 많아서, 뽑힌 프레임이 캐릭터 디자인 6장의 "5~6색 셀 음영" 규칙에서 벗어날 수 있다 — 5-6(검수)·5-8(후처리)에서 별도로 다룬다.

### 5-2. 기준 앵커(초안) 이미지부터 고정 — 코덱스 담당
- 동물마다 가장 먼저 **"마스터 캐릭터 시트" 1장**을 코덱스로 생성·확정한다 — **3/4 뷰**(정면 아님, 캐릭터 디자인 5-6 기준) 기본 서 있는 포즈, 등신 비율(캐릭터 디자인 5-5 표), 5~6색 컬러 예산(캐릭터 디자인 6장, 아웃라인 #202024 고정), 캡슐형 실루엣을 전부 반영.
- **이 앵커 이미지가 확정되기 전까지 해당 동물을 시댄스로 넘기지 않는다** — 비율·색이 틀린 초안을 영상화하면 전부 다시 만들어야 한다.
- 앵커 프롬프트에는 동물 베이스/쉐이드/포인트 컬러를 **정확한 헥스 코드**로 명시한다 — 이 헥스 값은 5-3의 시댄스 프롬프트에도 그대로 반복 사용한다.
- **투명 PNG는 Codex imagegen 스킬의 기본 투명 처리 절차를 적용한다.** 생성 단계에서는 캐릭터와 겹치지 않는 완전 단색 크로마키 배경을 사용하고, 생성 후 스킬 내 `scripts/remove_chroma_key.py`를 `--auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill` 옵션으로 실행해 알파를 추출한다. 헬퍼 내부의 `ALPHA_NOISE_FLOOR = 8` 처리가 미세 반투명 알파 노이즈를 0으로 정리한다. 가장자리에 키 컬러 테두리가 남을 때만 `--edge-contract 1`을 한 차례 추가하며, 셀 애니메이션의 또렷한 외곽선을 흐릴 수 있는 `--edge-feather`는 기본적으로 쓰지 않는다.
- **시트 생성본과 게임용 투명본을 분리한다.** AI에는 캐릭터와 겹치지 않는 단색 크로마키 배경만 생성하게 하고, 정확한 그리드선은 AI가 그리게 하지 않는다. 알파 추출·검수 후 로컬 후처리에서 시트 전체에 1px 그리드를 합성한다.
- **그리드 규격:** 마스터 시트는 동일 크기 셀로 나누고, 경계선은 RGBA 단색으로 직접 그린 정확한 **1px 직선**만 사용한다. 안티에일리어싱·블러·글로우·그림자·그라데이션·번짐을 금지한다. 모든 캐릭터와 소품의 불투명/반투명 픽셀은 자기 셀 안쪽 안전영역에 완전히 포함되어야 하며, 그리드선과 최소 **24px** 이상 떨어뜨린다. 그리드선을 침범하거나 닿은 생성물은 불합격으로 보고 재생성 또는 재배치한다.
- **프레임 독립 공간 규칙:** 시퀀스 시트에서 각 셀은 그 셀만 사각형으로 잘라 사용해도 완전한 단일 스프라이트가 되어야 한다. 캐릭터의 좌·우·상·하 최외곽 알파 픽셀은 셀 경계에서 최소 **5px 이상** 떨어져야 하며, 인접 프레임의 손·발·주둥이·귀·뿔·꼬리·소품·안티에일리어싱 픽셀이 자기 셀 안으로 들어오면 안 된다. 주둥이 아래처럼 빈 공간이 있더라도 다른 프레임의 신체를 끼워 넣어 시트를 압축하는 **인터로킹 배치**를 금지한다. 24px 여백을 확보할 수 있는 마스터 시트에서는 24px을 우선 사용하고, 리사이즈·최종 패킹 뒤에도 5px은 절대 하한으로 유지한다.

### 5-3. 실제 모션은 시댄스에서 — 앵커 이미지 + 모션 프롬프트 → 영상 → 프레임 추출
- 이동·성공/실패·캡슐 등장·개별 액션 등 실제 움직임은 코덱스가 아니라 **시댄스에 앵커 이미지를 입력으로 넣고, 동작을 설명하는 짧은 모션 프롬프트**(예: "제자리에서 통통 튀며 뛰는 동작")를 줘서 영상으로 뽑는다.
- 생성된 영상에서 **필요한 프레임만 균등 간격으로 추출**해 시퀀스 텍스처로 만든다 — 아래 5-4 표의 "프레임 수"는 시댄스에 요청하는 생성 길이가 아니라, **영상에서 최종적으로 뽑아 쓸 프레임 수**를 뜻한다.
- 영상 생성이라 프레임 간 일관성은 어느 정도 자연히 확보되지만, 앵커 이미지에서 실루엣이 크게 벗어나지 않는 **짧고 단순한 모션 프롬프트**를 쓰는 게 안전하다 — 복잡한 동작을 한 번에 요청하면 영상 중간에 형태가 무너질 위험이 있음.

### 5-4. 프레임 수 예산 — 영상에서 뽑아 쓸 프레임 수
프레임이 많을수록 일관성이 깨질 확률(과 후처리 분량)이 함께 올라간다. 아래를 상한으로 잡는다.

| 애니메이션 | 추출 프레임 수 상한 | 비고 |
|---|---|---|
| 정지 포즈 | 1 | 신규 생성 없음 — 앵커 이미지 자체를 재사용, 시댄스 불필요 |

- 프레임 사이 움직임은 영상에서 더 많은 프레임을 뽑는 대신 **Godot 쪽에서 스케일·회전·포지션 트윈**으로 메꾸는 걸 기본값으로 한다 — "짧은 영상에서 프레임 몇 장 추출 + 코드 보간"이 이 파이프라인의 기본 공식.

### 5-5. 생성 순서 — 파일럿 후 확장
1. **파일럿 2종**: 원안에 있던 악어·새로 먼저 **코덱스(앵커) → 시댄스(모션 영상) → 프레임 추출 → 후처리**까지 파이프라인을 끝까지 돌려보고 병목·일관성 문제를 먼저 검증한다.
2. 파일럿이 5-6 체크리스트를 통과하면 나머지 메인 로스터 동물(카피바라·비버·다람쥐·두더지·캥거루·펠리컨·여우·곰·코알라·수달 콤비·코뿔소·판다·하마)로 순서대로 확장.
3. 3장 표에 아직 남아있는 후보(염소·플라밍고·스컹크·앵무새 등)는 출시 로스터가 확정된 뒤 착수한다 — 미확정 스펙에 파이프라인을 낭비하지 않는다.

### 5-6. 생성물 검수 체크리스트
프레임 하나를 완성으로 처리하기 전에 확인한다.
- 아웃라인 색이 #202024로 고정되어 있는가
- 동시에 쓰인 색이 5~6가지(캐릭터 디자인 6장)를 넘지 않는가
- 등신 비율이 캐릭터 디자인 5-5 표의 배정값과 눈으로 봐도 어긋나지 않는가
- 실루엣이 캡슐형(관절·근육 표현 없음) 원칙을 유지하는가
- 앵커/이전 프레임 대비 색상·비율이 흔들리지 않았는가
- **시댄스가 그라데이션·블러를 넣지 않았는가** — 있다면 5-8 후처리 대상
- 캐릭터 본체·꼬리·귀·소품·알파 가장자리까지 자기 셀의 24px 안전영역 안에 들어가며 1px 그리드선과 닿지 않는가
- 최종 PNG가 RGBA이고 모서리 및 캐릭터 외부가 완전 투명(alpha 0)인가; 경계에 크로마키 색 번짐이나 1~8 수준의 미세 알파 노이즈가 남지 않았는가
- 그리드선이 후처리로 합성된 정확한 1px 단색선이며 안티에일리어싱·블러·글로우·그림자가 전혀 없는가
- 각 셀을 독립적으로 잘랐을 때 해당 프레임의 캐릭터 한 개만 존재하는가; 네 방향 최외곽 알파 픽셀이 셀 경계에서 최소 5px 이상 떨어지고 인접 프레임 픽셀 침범이 0개인가

### 5-7. 실패 시 폴백
같은 앵커에서 시댄스로 뽑아도 일관성이 계속 깨지는 동물이 있다면, 그 동물은 5-4 표보다 추출 프레임 수를 더 줄이거나(예: 이동 4→2), 모션 프롬프트를 더 단순하게 바꾸거나, 사람이 직접 색보정·리터치를 한 번 거치는 단계를 추가한다 — 로스터 전체를 100% 자동 생성으로 밀어붙이지 않는다.

### 5-8. 색상 후처리 — 시댄스 결과물을 셀 음영 규칙에 맞추기
- 영상 생성 툴은 카툰 셀 음영보다 부드러운 그라데이션·모션 블러에 최적화돼 있는 경우가 많아, 시댄스에서 추출한 프레임은 캐릭터 디자인 6장의 "그라데이션 없는 셀 음영 1단" 규칙을 그대로 만족하지 못할 가능성이 있다.
- 추출한 프레임마다 **색상 포스터라이즈(색 수를 6장 컬러 예산에 맞춰 강제로 줄이는 처리)** 또는 아웃라인 재추출 같은 후처리 단계를 파이프라인에 기본으로 넣어야 할 수 있다 — 아직 코덱스로 자동화할지, 별도 툴/스크립트로 처리할지는 미정이라 착수 시점에 결정 필요.
- Codex 정지 앵커의 투명화는 별도 범용 디노이저가 아니라 imagegen 스킬의 `remove_chroma_key.py`가 담당한다. `--soft-matte`로 안티에일리어싱 경계의 알파를 계산하고, `--despill`로 키 컬러 번짐을 제거하며, 내장 `ALPHA_NOISE_FLOOR = 8`로 아주 약한 반투명 잡음을 완전 투명으로 정리한다. 이 처리는 캐릭터 내부의 셀 면을 뭉개는 공간 블러가 아니므로 원본 실루엣과 1px 그리드를 보존한다.
- **처리 순서는 고정한다:** 크로마키 원본 생성 → 알파 추출/노이즈 정리 → 캐릭터 픽셀의 셀 안전영역 검사 → 필요 시 위치·스케일 보정 → 마지막에 1px 그리드 합성. 그리드 합성 후에는 리사이즈·블러·재인코딩을 하지 않는다.
- 셀 안전영역 검사는 시트 전체의 연결요소 개수만 세는 것으로 끝내지 않는다. 각 셀을 실제 출력 규격으로 잘라 알파 바운딩박스를 계산하고 `left`, `top`, `right`, `bottom` 여백이 모두 5px 이상인지 확인한다. 셀 경계를 가로지르는 연결요소나 이웃 셀에서 넘어온 고립 픽셀이 하나라도 있으면 해당 시트는 불합격이다.

### 5-9. 산출물 저장 규칙 (제안)
현재 프로젝트(`apps/game-lhj-animal`)에는 아직 assets 폴더가 없어 확정 규칙은 아니지만, 착수 시 `assets/characters/<동물영문명>/<애니메이션명>/frame_00.png` 형태의 동물→애니메이션→프레임 계층 네이밍을 제안한다. 좌우 반전본은 별도 파일로 저장하지 않고 엔진에서 flip 처리(0장 원칙)하므로 저장 대상에서 제외한다.

## 6. 곰 달리기 파일럿에서 확정한 실전 제작 규칙 *(2026-08-12 17:27 기준)*

곰 캐릭터 달리기 애니메이션을 여러 차례 생성·조합·후처리하면서 확인한 규칙이다. 이후 다른 동물의 공용 이동 애니메이션을 만들 때도 이 절차를 기본값으로 사용한다. 기준 산출물은 `assets/bear_run_stabilized/` 아래의 12프레임 결과이며, 사람이 고른 하체 순서는 `assets/bear_run_natural/순서.txt`의 `03-01-04-15-02-17-24-22-07-06-23-26`이었다.

### 6-1. 프레임 수보다 동작 순서를 먼저 확정

- 처음부터 4장·8장처럼 프레임 수를 강제하지 않는다. 먼저 **동작에 반드시 필요한 키포즈를 시간 순서로 정의**하고, 생성 결과에서 실제로 쓸 수 있는 포즈만 고른다.
- 두 발 달리기는 플레이어 화면 기준으로 좌우를 정의한다. 캐릭터 몸통의 화면 오른쪽에 보이는 다리를 오른발, 화면 왼쪽에 보이는 다리를 왼발로 부른다. 프롬프트마다 이 정의를 반복해 해석이 바뀌지 않게 한다.

- 생성된 여러 후보를 사람이 다시 조합할 수 있다. 이 경우 파일명 순서가 아니라 `순서.txt`를 최종 재생 순서의 단일 기준으로 삼는다.

### 6-2. 프레임마다 반드시 유지할 것과 움직여도 되는 것

**고정에 가까워야 하는 요소:**
- 캐릭터 3/4 방향과 카메라
- 머리 크기·얼굴 각도·눈·주둥이 위치
- 모자·베일 등 머리 장신구의 크기와 기울기
- 어깨 폭·몸통 폭·셔츠 목선과 밑단
- 캐릭터 전체 스케일과 화면상 중심축

**움직여야 하는 요소:**
- 좌우 다리의 전진·착지·밀기·교차
- 선행 다리와 반대로 움직이는 양팔의 카운터 스윙
- 착지 때 낮아지고 밀어낼 때 높아지는 작은 상하 바운스
- 필요한 범위 안의 가벼운 스쿼시·스트레치

상체를 안정시킨다는 이유로 상체 픽셀 한 장을 모든 프레임에 덮어쓰면 안 된다. 그러면 팔 스윙과 자연스러운 바운스까지 사라져 **애니메이션 정보가 삭제**된다. 상체 안정화는 형태·중심축의 일관성을 뜻하며, 상체 전체의 정지화를 뜻하지 않는다.

### 6-3. 떨림 제거 — 전체 바운딩박스가 아니라 상체 앵커로 정렬

- 프레임의 전체 알파 바운딩박스 중심으로 정렬하지 않는다. 다리를 넓게 벌린 프레임에서 하체 폭이 중심 계산에 섞여 상체가 반대쪽으로 밀리며, 재생 시 캐릭터가 좌우로 덜덜 떨게 된다.
- 플레이어 색 마스크가 있는 캐릭터는 **마젠타 셔츠의 중심**을 상체 위치 앵커로 쓴다. 셔츠가 없다면 가슴 중심, 목선, 양어깨 중점처럼 하체 변화에 영향을 받지 않는 기준점을 쓴다.
- 곰 파일럿에서는 셔츠 중심이 프레임별로 가로 약 9px, 세로 약 7px 흔들려 눈에 띄는 진동이 생겼다. 모션과 크기는 유지한 채 각 프레임을 평행 이동하여 셔츠 중심 좌표만 통일하자 큰 위치 진동이 사라졌다.
- 정렬 때 프레임별 스케일을 다시 맞추지 않는다. 매 프레임 자동 리사이즈를 하면 머리와 모자가 숨 쉬듯 커졌다 작아지는 스케일 펌핑이 생긴다. 모든 프레임은 같은 스케일을 유지하고 **위치만 보정**한다.

### 6-4. 색상 교정과 디노이징의 정확한 범위

- 재생성·편집을 반복하면 동물 베이스 컬러가 조금씩 바뀐다. 애니메이션에 쓰인 모든 프레임을 기준 앵커 이미지에서 추출한 동일 팔레트로 정규화한다.
- 곰 파일럿의 원본 기준 팔레트는 암부 `#322217`, 그림자 `#4B3221`, 베이스 `#603F27`, 밝은 주둥이 `#8B6C4E`였다. 이 값은 곰 전용 사례이며, 다른 동물은 각자의 확정 앵커에서 새로 추출한다.
- 색상 교정은 동물 털 픽셀에만 적용한다. 마젠타 셔츠, 모자, 베일, 눈, 하이라이트, 아웃라인과 고유 소품은 변경하지 않는다.
- 여기서 **디노이징은 동작이나 실루엣을 없애는 작업이 아니다.** 팔·다리·상체 바운스를 포함한 각 프레임의 원래 픽셀 배치는 유지하고, 색상 팔레트 밖의 미세 얼룩과 alpha 1~8 수준의 잔여 반투명 픽셀만 정리한다.
- 공간 블러·프레임 평균·상체 한 장 덮어쓰기·프레임 복제는 디노이징으로 취급하지 않으며 금지한다. 이 방식은 외곽선을 무르게 하거나 애니메이션 정보를 삭제한다.
- 후처리 뒤에는 인접 프레임끼리 충분한 픽셀 차이가 남아 있는지 검사한다. 팔·다리 모션이 정상이라면 모든 프레임이 사실상 같은 그림으로 수렴해서는 안 된다.

### 6-5. 권장 작업 순서

1. 동물별 마스터 앵커 이미지와 정확한 베이스 팔레트를 확정한다.
2. 프레임 수를 정하기 전에 이동 동작의 필수 키포즈 순서를 문장으로 정의한다.
3. 이미지 생성 시 앵커와 동작 순서를 함께 제공하고, 동일 3/4 방향·스케일·상체 축을 반복 명시한다.
4. 후보 프레임 중 다리 순서가 맞는 것만 골라 `순서.txt`에 재생 순서를 기록한다.
5. 선택한 프레임의 팔 스윙·다리 모션·상체 바운스를 유지한 채 상체 앵커 좌표로 평행 이동 정렬한다.
6. 기준 앵커에서 추출한 동물 전용 팔레트로 털/피부색만 정규화한다.
7. imagegen 투명 처리 절차로 크로마키 제거·despill·알파 노이즈 정리를 적용한다.
8. 개별 프레임, 투명 시트, 12fps 검토용 GIF/WebP를 함께 생성해 루프·떨림·색 흔들림을 최종 검수한다.

### 6-6. 실패 사례 — 반복 금지

- **프레임 수부터 강제:** 동작상 필요하지 않은 중복 포즈가 생기거나 발 순서가 꼬였다.
- **서로 다른 생성 세트의 프레임을 무보정 혼합:** 다리 흐름은 맞아도 머리·모자·어깨·셔츠 폭이 프레임마다 달라 상체가 뒤틀렸다.
- **전체 캐릭터 바운딩박스 중앙 정렬:** 다리 벌림 폭에 따라 상체가 좌우로 흔들렸다.
- **상체 하드락:** 머리 떨림은 없어졌지만 팔 애니메이션과 상체 바운스까지 사라졌다. 최종 애니메이션 제작에는 사용하지 않는다.
- **하드락 결과에 색상 교정:** 이미 모션이 삭제된 결과를 후처리했기 때문에 색은 맞아도 잘못된 산출물이었다. 색상 교정은 반드시 모션이 살아 있는 원본 프레임에 적용한다.

### 6-7. 다른 동물에 적용할 때

- 다리 구조가 비슷한 이족보행 동물은 곰의 키포즈 순서를 공용 출발점으로 쓴다.
- 꼬리가 큰 비버·다람쥐·여우·캥거루는 전체 바운딩박스 정렬 오차가 더 커질 수 있으므로 상체 앵커 정렬을 반드시 사용한다.
- 부리가 긴 새·펠리컨, 뿔이 긴 코뿔소는 머리 장식/신체 특징이 셀 경계를 넘지 않도록 안전 여백을 별도 확인한다.
- 수달 콤비는 두 캐릭터 각각의 상체 앵커와 둘 사이 연결 리본의 중심을 함께 관리해야 한다.
- 모든 동물에서 최종 기준은 동일하다: **모션은 보존하고, 위치·색·알파 노이즈만 보정한다.**

## 7. 코뿔소 24프레임 파일럿 — 고밀도 생성과 중복 검사 *(2026-08-13)*

코뿔소 달리기에서 적은 키포즈만 생성했을 때 같은 자세가 반복되어 보이는 문제를 줄이기 위해, 한 사이클을 **24개 시간 단계**로 세분화한 고밀도 파일럿을 진행했다. 산출물은 `assets/rhino_run_24f/`에 저장했다.

### 7-1. 24프레임 구성

- 1~12프레임: 오른발 선행 반주기. 발 들기 → 무릎 전진 → 정강이 펴기 → 최대 전방 도달 → 첫 접지 → 완전 접지 → 최저 압축 → 밀어내기 → 몸 아래 통과 → 후방 이동 → 반대발 전진으로 이어진다.
- 13~24프레임: 왼발 선행 반주기. 위 과정을 반대발 기준으로 반복하고 24번이 1번으로 연결된다.
- 인접 프레임은 무릎 각도·발 위치·골반 높이·팔 위치 중 최소 하나가 눈에 띄게 달라야 한다.
- 좌우 반주기는 역학적으로 대응해도 실제 선행 다리와 카운터 스윙 팔이 반대이므로 동일 이미지 복제가 아니다.

### 7-2. 중복 검사 규칙

- 생성 후 모든 프레임을 동일 셀·동일 스케일·상체 앵커 위치로 정규화한 다음 비교한다.
- 알파 실루엣을 기준으로 32×32 perceptual aHash의 해밍 거리와 64×64 알파 평균 절대 차이를 함께 계산한다.
- 인접 프레임만 보지 않고 24장 전체 조합 **276쌍**을 검사한다.
- 완전 중복은 해밍 거리 0이면서 알파 차이가 0.5% 미만인 쌍으로 간주하고 불합격 처리한다.
- 근접 중복은 해밍 거리 20 이하이면서 알파 차이가 3.5% 미만인 쌍으로 표시한다. 촘촘한 인비트윈 특성상 일부 근접 쌍은 정상일 수 있지만, 시간상 멀리 떨어진 프레임끼리 닮았으면 중복 포즈 후보로 검토한다.
- 코뿔소 파일럿 결과는 완전 중복 0쌍, 근접 중복 8쌍이었다. 상세 결과는 `assets/rhino_run_24f/duplicate-report.txt`에 보관한다.

- 투명 한 줄 스프라이트 시트 1장
